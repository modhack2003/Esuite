## Findings

1. **Major — browser output meets the navigation edge that the driver rejects.** Affected scope: `MainActivity.kt:81`, `browser/BrowserScreen.kt:67-79,126-169`, `NativeUiDriver.java:33-44`, `ProductionUiTest.java:56`. The new browser receives the entire bounded content height, gives the remaining Page space to the WebView, and places its final short output directly at the bottom without a trailing inset. The driver's `usable()` rejects anything whose bottom is not strictly above `nav_home.top - 3`. Consequently the initial `output("Page loaded")` can reject the genuinely visible output and exhaust its lookup before the paint oracle even runs. Add a small bottom content inset, or distinguish readable clipped text from actionable controls with viewport-based bounds. Acceptance: run the real Page-loaded assertion and retain its screenshot/tree with nonzero WebView bounds and readable output above navigation. This is a source-derived geometry issue, not a device-confirmed failure or a diagnosis of the user's previous black screen.

2. **Major — scrolling gestures miss the newly inset inspector viewport.** Affected scope: `MainActivity.kt:81`, `browser/BrowserScreen.kt:126-127`, `NativeUiDriver.java:46-56,110-113`. The browser now has 8dp horizontal padding, while every search/reset swipe starts at 1% of display width. On normal phone widths that x coordinate lies outside the inspector's scrollable hit region. An output or control clipped below this bounded panel cannot be brought into view by `find()`/`top()`, especially after long evaluation output or on a shorter viewport. Target a tagged inspector scroll container and use coordinates inside its visible bounds, or use its scroll semantics. Keep the existing full-page fallback for the immutable 1.0.1 upgrade baseline. Acceptance: exercise lower Elements/Cookies output and return-to-top on the optimized APK with screenshots; baseline seed/restart and updated-app retained-note checks must still pass without clearing data.

## Reviewed behavior with no additional blocking finding

- The Page/inspector hierarchy keeps the keyed `AndroidView` composed while changing its height, so switching panels alone does not intentionally recreate the WebView. The screenshot oracle checks the actual WebView's visible bounds against a two-color page pattern and rejects blank white/window-background images. This is useful paint evidence; only an actual optimized/signed APK run establishes that it passes.
- Loading remains an explicit Go action. Profiles remain keyed by project/identity and unsupported profile providers disable Browser. File/content access is disabled, mixed content is rejected, and TLS errors are cancelled. Exact-origin main-frame checks and the explicit metadata-only provenance remain present; no full interception or TLS-pinning bypass is established.
- The shared driver still has no data reset. Only `ProductionUiTest` clears disposable emulator data. `UpgradeUiTest` seeds and verifies an observation after a baseline process restart, and the signed runner pins the 1.0.1 URL/SHA before installing the update with `-r`. Preserve those boundaries when fixing driver scrolling.
- `CapturedText.decode()` uses replacement for malformed/unmappable interior bytes and non-final decoder input for a truncated capture. This preserves interior replacement behavior while leaving only incomplete terminal input unconsumed. The focused test includes malformed interior UTF-8 and valid U+FFFD; valid split-prefix cases cover UTF-8, UTF-16BE and Shift_JIS. No decoder correctness issue was identified in the bounded input path.

## Resolution recheck

Source rechecked after the root fixes on 15 November 2026. Both findings are addressed at source level:

- Finding 1: `BrowserScreen.kt:67` now applies an 8dp bottom inset, leaving the final Page output above the navigation-edge exclusion in `usable()`.
- Finding 2: the inspector now exposes `browser_inspector`; `scrollBounds()` uses that node's visible rectangle when inspector tabs are active, and both search/reset swipes start inside its left edge and use its vertical bounds. The old full-page x coordinate and display-relative y coordinates remain the fallback, including the immutable 1.0.1 baseline where `browser_url` remains composed. The Page/Elements helper switches and select-element-to-Page transition remain present.

No remaining source-review blocker was identified in this focused scope. Actual optimized-APK Page paint, inspector reachability and same-signer baseline upgrade execution remain acceptance gates; this recheck does not claim a build/device pass.
